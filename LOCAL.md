# Локальные доработки поверх videro-skill

Форк апстрима `vakovalskii/videro-skill` с обвязкой под свои прогоны.
**Апстримные файлы не изменены ни на строку** — всё, что меняет их поведение,
сделано подменой атрибутов снаружи, поэтому `git pull origin main` не конфликтует.

---

## Быстрый старт

```bash
./run.sh all путь/к/видео.mp4
```

Одна команда делает всё: разметку, нормализацию терминов, диаризацию, главы,
проверку на секреты — и печатает ссылку на плеер.

Флаги: `--name` (имя папки), `--title` (заголовок страницы), `--lang` (по умолчанию `ru`),
`--serve` (сразу поднять плеер), `--hls` (сделать транскод), `--force` (переделать всё).

**Прогон можно прерывать.** Состояние берётся из самого `timeline.json`, а не из
файлов-меток: есть сцены — разметка была, есть `text_asr` — нормализация прошла,
есть `speaker` — диаризация сделана, есть `chapters` — главы собраны. Перезапуск
доделывает с места обрыва. Для двухчасовой записи это экономит ~18 минут
распознавания при падении на позднем шаге.

Дальше: открыть плеер → «Назвать спикеров» → вписать имена → «Сохранить».

## Отдать результат коллегам

```bash
./run.sh package имя-папки
```

Кладёт рядом `videro-out/имя-share.zip`: видео, разметка, плеер и сервер на
стандартной библиотеке. Получателю нужен только Python 3 — ни ключей, ни venv,
ни интернета. Внутри `start-mac.command`, `start-windows.bat`, `start-linux.sh` —
двойной клик и открывается браузер.

Открыть `index.html` из файла нельзя: браузер запрещает `fetch` с `file://`,
поэтому `timeline.json` не прочитается, а без Range-запросов не перематывается
большое видео. Отсюда сервер в комплекте.

## Все команды

| Команда | Что делает |
|---|---|
| `./run.sh all видео.mp4` | весь путь разом (см. выше) |
| `./run.sh local видео.mp4 --out DIR` | разметка: локальный whisper + сцены |
| `./run.sh normalize DIR/timeline.json` | привести термины к `glossary.txt` |
| `./run.sh diarize видео.mp4 --timeline DIR/timeline.json` | кто когда говорит |
| `./run.sh chapters DIR/timeline.json` | главы и отбор хайлайтов |
| `./run.sh speakers DIR/timeline.json` | реестр спикеров (обычно не нужно, есть кнопка в плеере) |
| `./run.sh redact DIR/timeline.json --ocr` | вычистить секреты |
| `./run.sh serve videro-out/имя [порт]` | поднять плеер |
| `./run.sh package имя` | собрать архив для раздачи |
| `./run.sh asr медиа --lang ru` | только распознавание, без разметки |

**Порядок в `all` не произвольный:** нормализация до глав (иначе в оглавлении
останется кириллица вместо терминов), диаризация до глав (`chapters.py` ставит
границы по смене докладчика).

## Что и зачем добавлено

### Локальный whisper вместо SpeechCore

`scripts/asr_local.py` + `scripts/videro_local.py`. Апстрим берёт транскрипт из
SpeechCore, но сервис недоступен (TLS отвечает, HTTP виснет). Взамен —
`mlx-whisper` с `large-v3` на Metal, около **12× реалтайма** на M4.

Обёртка подменяет `analyze.transcribe` снаружи, апстримный `analyze.py` цел.

Whisper не даёт диаризацию — её кладёт отдельный шаг.

### Ретраи: `scripts/hub_retry.py`

Hub отдаёт 429 при четырёх воркерах, и апстрим на этом разваливается **молча**:
`describe_scene` не ретраится вообще (сцена превращается в пустышку с текстом
ошибки в `action`), а `_fix_call` ретраит трижды без пауз, поэтому вся коррекция
субтитров проваливается целиком и выглядит как «модель не нашла ошибок».

Лечится подменой `analyze.requests` на сессию с urllib3-Retry (backoff 2→32 с).
До: 1 потерянная сцена и 0 исправлений из 113. После: 0 потерь, 18 из 113.

### Главы: `scripts/chapters.py`

**Из коробки главы не собираются.** README апстрима советует группировать сцены
по `topic`, но `analyze.py` размечает каждую сцену независимо и параллельно,
поэтому единого словаря тем не возникает: на тесте вышло 17 уникальных тем на
19 сцен, то есть по «главе» на сцену.

Второй проход отдаёт все сцены одним запросом и получает настоящее оглавление.
Особенности:

- **батчинг** по 60 сцен со сквозной нумерацией (`--chunk`);
- **цель по куску пропорциональна его размеру** — иначе короткий последний кусок
  дробился вдвое мельче остальных;
- **склейка через границу**: следующий кусок получает заголовок предыдущего и
  повторяет его дословно, одинаковые соседние объединяются. Без этого тема на
  стыке резалась пополам;
- **границы по смене докладчика навязываются кодом**. Просить об этом модель
  бесполезно — она держит цель по числу глав и подсказку игнорирует (5 границ
  из 27). Сейчас: `speaker_boundaries` считает границы, промпт требует их,
  `force_splits` дорезает, если модель всё равно проигнорировала. Порог
  `--speaker-split N`, по умолчанию 3 сцены;
- **название по речи, а не по картинке** (`CHAPTERS_SPEECH_CAP`, по умолчанию 450).
  На 260 символах фраза рубится посередине, и глава про десктопное приложение
  получала название про VS Code — единственное уцелевшее в обрезке имя продукта.

Хайлайты отдаются отсортированными по времени; `importance` только отбирает топ-N.

### Диаризация: `scripts/diarize.py`

`pyannote.audio` с `speaker-diarization-community-1`. Модель гейтед — нужен
`HF_TOKEN` в `.env` и принятые условия на HuggingFace.

Около **12.7× реалтайма** на MPS. MPS и CPU дают побитово одинаковый результат
на этом железе (проверено: расхождение границ 0 мс), известная проблема с
таймкодами на Apple Silicon не воспроизводится.

Ложится поверх готового транскрипта по максимальному перекрытию — **ASR
перегонять не надо**. `--num-speakers`, если число говорящих известно.

Диаризация и `chapters.py` оба пишут `timeline.json` — только последовательно.

### Имена спикеров: `scripts/speakers.py` + кнопка в плеере

Диаризация даёт безымянные `SPEAKER_00`. Опознать может только человек, поэтому
в плеере есть «Назвать спикеров»: метка, доля речи, число реплик и по два первых
содержательных примера с кликабельными таймкодами. Имя уходит в
`transcript[].speaker_name` и в субтитры префиксом.

Исходные метки не затираются — накат обратим и повторяем, пересборка реестра
не теряет вписанные имена.

### Термины: `scripts/normalize.py` + `glossary.txt`

Русская речь с английскими терминами распознаётся на слух: «харнес» вместо
harness, «клод» вместо Claude.

**Глоссарий в `initial_prompt` не помогает** — проверено в трёх конфигурациях,
искажённый термин остаётся во всех. Настоящая причина: whisper пишет `harness`
или «харнес» в зависимости от того, где прошла граница 30-секундного окна.
На один и тот же звук даёт оба варианта, управлять этим нельзя.

Поэтому чиним после. Правки проходят **детерминированный фильтр**: принимается
только та, где каждый изменённый фрагмент вводит слово из словаря. Модель,
несмотря на прямой запрет в промпте, правит постороннее — на лекции отклонено
13 правок, включая добавление «не», переворачивающее смысл фразы.

Результат на лекции: «харнес/хармис/хармас» 9 → 0, «клод» 3 → 0, «ллм» 3 → 0.
Оригиналы сохраняются в `text_asr`.

`glossary.txt` — обычный текстовый список, дополняй под свои проекты.

### Секреты: `scripts/redact.py`

**Пайплайн переносит секреты с экрана в текст.** Апстримный `fix_subtitles`
«исправляет» реплики по OCR-контексту и подставляет то, чего в речи не было.
На лекции whisper услышал описание словами («джей подчёркивание токен равно
токен который вы вставили»), а после коррекции в транскрипте оказались
настоящий `JIRA_TOKEN` и почта.

Очистка встроена в два места и не полагается на память:
- в конце прогона, **до** записи `timeline.json` на диск (`videro_local.py`);
- перед отправкой промпта в API (`chapters.py`, `normalize.py`) — `on_screen_text`
  уходит в Hub при каждом прогоне.

Отключается `NO_REDACT=1`. Вручную: `./run.sh redact ... --dry-run` / `--ocr`.

Три слоя правил: известные форматы (ATATT/JWT/`sk-`/`gh_`/AKIA/AIza/xox/Bearer/почта),
`КЛЮЧ=значение`, и улов на неизвестные форматы — длина 32+ плюс оба регистра плюс
цифра. Последнее не трогает git-хеши (только нижний регистр), пути (слэш) и имена
токенов. Понадобилось после находки: `Authentication code / Paste this into
Claude Code: <92 символа>` не ловился ничем из списка известных.

Имена переменных сохраняются, вырезаются только значения.

### Плеер: `player/` + `scripts/serve.py`

Одна страница, читает папку прогона из `?src=`. Главы, хайлайты, транскрипт
(всё кликабельно), карточка «сейчас в кадре», полоса сцен с хайлайтами,
метки спикеров, субтитры (SRT→VTT конвертится в браузере — `<track>` не ест SRT).

`hls.js` лежит локально, CDN не нужен. Если в папке есть `hls/master.m3u8` —
играет его, иначе `video.mp4`.

Свой сервер вместо `python -m http.server` по двум причинам: тот **не умеет Range**
(без него браузер не перематывает большой mp4 — на 590 МБ клик по главе не
работает), и не умеет писать, а кнопке имён нужен POST. Есть защита от выхода
за корень раздачи и `no-store` для `.json`.

## Грабли, которые стоит помнить

- **`--no-hls` пропускает не только транскод, но и постер** — обе строки в одном
  `if` (`videro.py:63-66`). `pipeline.py` делает обложку сам.
- **Транскод раздувает вес**: `transcode.py` жмёт 720p в 2400 кбит/с независимо
  от исходника. Из 19 МБ ютубовского AV1 вышло 195 МБ HLS. Для скринкастов
  потолки надо опускать.
- **Детекция сцен на скринкастах почти не работает**: там нет резких переходов,
  и окна режутся ровной 30-секундной сеткой. Частично компенсируется границами
  по смене докладчика.
- **`FIX_PROMPT` апстрима утверждает, что на входе «сегменты русской речи»** —
  для англоязычного видео это неверно, но шаг всё равно работает.
- **Транскрипт не улучшает разметку сцен.** Ожидалось, что речь в промпте
  `describe_scene` поднимет качество тем и хайлайтов — прогон с речью и без дал
  17 уникальных тем в обоих случаях. Причина архитектурная, речью не лечится.
  Главы даёт только второй проход.

## Окружение

`.env` (в `.gitignore`): `NEURALDEEP_API_KEY` обязателен, `HF_TOKEN` для диаризации,
`SPEECHCORE_TOKEN` не нужен. Скрипты читают только `os.getenv`, `.env` сам не
подхватывается — его грузит `run.sh`.

`.venv` с `mlx-whisper`, `pyannote.audio`, `playwright`, `yt-dlp`.
Модели в `~/.cache/huggingface`: whisper ~2.9 ГБ, pyannote ~31 МБ.
