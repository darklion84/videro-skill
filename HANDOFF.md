Если оборвалась — просто повторить, оба шага идемпотентны:

```bash
./run.sh normalize videro-out/lecture2/timeline.json
./run.sh chapters  videro-out/lecture2/timeline.json
```

1. Имена спикеров целы: `speaker_name` должен быть у ~1693 реплик. Пользователь
   вписывал их вручную, потерять нельзя.
2. Пустых сцен по-прежнему 0.
3. Главы: раньше была одна на 33 сцены (~16 минут) — ожидается, что распадётся,
   потому что раньше модель видела пустоту на половине лекции.
4. Инварианты: стыки без дыр, покрытие полное, дубли заголовков отсутствуют,
   все границы по смене докладчика поставлены.

Дальше — собрать архив: `./run.sh package lecture2 --hls`

## Дорого оплаченные грабли — не наступать снова

- **Потолок токенов.** Апстрим ставит `max_tokens=1600` в `describe_scene`. Плотный
  экран с кодом требует ~1522 — 95% лимита. Не влезший ответ приходит ПУСТЫМ
  (`finish=length`), `json.loads` падает, сцена становится заглушкой. Так осыпалось
  128 сцен из 273. Поднято до 4000.
- **`fix_subtitles` выключен.** Он заносил `JIRA_TOKEN` с экрана в транскрипт, его
  работу делает `normalize.py`, и прогон дважды умирал ровно на нём. Причина смерти
  НЕ установлена. Вернуть: `FIX_SUBTITLES=1`.
- **Не гонять `--force` на lecture2**: он перезапустит диаризацию, метки спикеров
  перетасуются и вписанные имена пропадут. Чинить сцены — только через отдельную
  папку и вклейку с проверкой границ.
- **Проверять гипотезы на всей выборке, а не на трёх примерах.** Дважды за сегодня
  сделал уверенный вывод по трём кадрам и по невалидному тесту (слал заглушку
  вместо настоящего промпта).
- **Бюджет перезапрашивать**, а не цитировать из прошлых ходов:
  `python3 ~/.claude/scripts/session-status.py`
